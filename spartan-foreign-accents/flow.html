Dashboard Data Flow

How a phone call becomes a row in the dashboard — from the moment it rings to the moment it shows up in Looker Studio.

The Four Systems
CallRail
Call Attribution
Tracks which marketing channel drove each call. Records it. Transcribes it. Forwards it to the shop. Staff picks up the same way they always have.
→
Make.com
Automation + AI Layer
Picks up every completed call from CallRail, writes it to Sheets, sends the transcript to Claude, and writes the AI output back. Runs automatically, 24/7.
→
Google Sheets
Data Warehouse
Every call lands here as a structured row — source channel, transcript, Claude analysis, and daily repair order entries. The single source of truth for the dashboard.
→
Looker Studio
Live Dashboard
Reads from Google Sheets and Google Ads. Refreshes every four hours. Five modules. Shareable via link — no login required for stakeholders.
Step-by-Step Flow
1
CallRail

Customer Dials a Tracking Number

Every marketing channel has its own unique CallRail tracking number. When a customer calls any of them, CallRail knows instantly which channel drove that call before the phone even rings at the shop.

Channel 1
Google Ads
Channel 2
Google Business Profile
Channel 3
Website Organic
Channel 4
Email Campaigns
Channel 5
Direct / Unknown
2
CallRail

CallRail Captures Everything, Then Forwards the Call

Before the call reaches the shop, CallRail captures four things in under a second. Then it forwards the call to the shop's real phone number. The staff picks up exactly as they always have. Nothing changes on their end.

Source Channel

Which tracking number was dialed — maps directly to the marketing channel.

Call Recording

Full audio of the call, stored in CallRail and available for review.

Transcript

Automatic text transcription of the full conversation, ready for AI analysis.

New vs. Returning

CallRail checks the caller's phone number against its history to flag first-time vs. repeat callers.

↪
Google Ads side connection: CallRail also imports call conversion events back into Google Ads. This means the Ads account can now see which campaigns are driving actual phone calls, not just clicks. Cost per call by campaign becomes visible for the first time.
3
Make.com

Make.com Picks Up the Completed Call

When the call ends, CallRail pushes a webhook to Make.com with the full call record: timestamp, source channel, duration, caller phone number, and raw transcript. Make is listening 24/7 and picks it up within seconds of the call ending.

If the webhook fails or CallRail is temporarily unreachable, Make retries automatically and logs the failure so nothing falls through without being noticed.

4
Google Sheets

Call Record Written to the Data Warehouse

Make.com writes a new row to the calls_log sheet with all the CallRail data. This row is the foundation. The Claude AI fields will be added to this same row in the next step.

Column Data Source
timestamp Date and time of the call CallRail
source_channel google_ads / gbp / web_organic / email / direct CallRail
call_duration_seconds Length of call in seconds CallRail
caller_phone Caller's phone number (hashed for privacy) CallRail
transcript_raw Full text of the call transcript CallRail
5
Claude API

Transcript Sent to Claude for Analysis

Make.com sends the transcript text to the Claude API with a structured prompt. Claude reads the conversation and returns a single JSON object — no summaries, no paragraphs. Just clean structured data that Make can parse and write directly to the spreadsheet.

Claude is instructed to return only valid JSON, so Make never has to guess the format. If a transcript is too short or empty to analyze (a missed call, a hangup), Make logs the error and moves on without breaking the workflow.

caller_type
"new" | "returning" | "unknown"

Whether this appears to be a first-time or repeat customer based on how they speak about the shop.

service_requested
plain text

What the caller asked about: oil change, brake job, diagnostic, AC repair, etc.

appointment_outcome
"booked" | "not_booked" | "transferred" | "voicemail" | "unclear"

Whether the call ended with a scheduled appointment or not.

reason_not_booked
plain text or null

If not booked: price concern, already booked elsewhere, just inquiring, no answer, etc.

special_mentioned
boolean

True if the caller referenced a weekly special by name or description.

special_name
plain text or null

Which special was mentioned, if any. Used to populate the Weekly Specials dashboard module.

sentiment
"positive" | "neutral" | "negative"

Overall tone of the caller based on word choice and context.

follow_up_needed
boolean

True if the call ended without resolution and the caller implied they'd call back or expected follow-up.

6
Google Sheets

Claude Output Written Back to the Same Row

Make.com parses the JSON response from Claude and writes each field as a separate column in the same calls_log row created in Step 4. The row now contains the full picture: where the call came from (CallRail) and what happened on it (Claude). No manual entry, no staff logging, no post-call forms.

An ai_processing_status column is also written: "success," "error," or "pending." This lets the error logging workflow catch any rows where Claude didn't return a valid response and retry them automatically.

7
Manual Entry

Daily Repair Order Entry (Revenue Layer)

Once a day, a staff member at the shop enters that day's repair orders into the ro_log sheet. Takes about two minutes.

Why manual and not automatic? The shop's management system (Steer) doesn't offer a public API, and the phone system (Yealink) isn't compatible with Steer's call intelligence features. A direct data connection isn't possible right now. The manual sheet is the practical workaround: it keeps revenue data in the dashboard without requiring the shop to change any systems. If Steer opens up API access in the future, connecting it directly is a straightforward upgrade.
Column Data
ro_date Date the repair order was created
customer_type New or returning
ticket_amount Total invoice value in dollars
service_category Primary service type (oil change, brakes, diagnostic, etc.)
special_referenced Weekly special tied to the RO, if applicable
8
Looker Studio

Looker Studio Builds the Live Dashboard

Looker Studio connects directly to Google Sheets (calls_log + ro_log) and to Google Ads via native connector. It refreshes every four hours automatically. The dashboard is shareable via link — Shane Beal, David Lasher, and the Spartan team can all access it without logging in anywhere.

Module 1

Volume & Revenue Overview

Total ROs vs. goal. Revenue vs. $125k target. Average ticket size trend. New vs. returning split.

Module 2

Lead Source Attribution

Calls by channel. Booked appointments by channel. Conversion rate by channel. Cost per call from Google Ads spend.

Module 3

New vs. Returning

New caller count, conversion rate, booked ROs, average ticket. Same breakdown for returning callers.

Module 4

Call Performance

Answered vs. missed. Conversion rate. Top reasons calls didn't book. Volume by day of week and time of day.

Module 5

Weekly Specials

Calls referencing each special. Booked ROs per special. Week-over-week comparison. Which specials are actually driving calls.
