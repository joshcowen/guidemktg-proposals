Every trigger originates inside WordPress: a form submission, a reviewer decision, a timer reaching a date. WordPress fires a webhook to HighLevel. HighLevel runs the matching sequence and sends the email. Nothing is manual.

Before Any Email Sends

Pre-Launch: Email Deliverability Setup

Domain Warming: Required Before Sequence 14

A new sending domain has zero reputation with inbox providers. This work has to happen first or the activation emails land in spam on launch day, regardless of how engaged the list is.
One-time setup
DNS records configured for sending subdomain
→
⚙

SPF, DKIM & DMARC Configuration

DNS records set up for SWSPCP's sending subdomain (e.g. mail.swspcp.org) inside HL. Tells inbox providers that HL is authorized to send on SWSPCP's behalf. Without this, emails fail authentication and get flagged immediately.

One-time setup
2-3 week ramp
Warming schedule: starts small, ramps up daily
→
⇧

Domain Warming Schedule

Send volume starts low (50-100 emails/day) and ramps up gradually over 2-3 weeks. Inbox providers see consistent, low-complaint mail from the new domain and build a positive reputation for it. This has to complete before Sequence 14 fires. Blasting 3,500 contacts from a cold domain skips the line and triggers spam filters.

Warm contacts used for ramp period
Ongoing during ramp
Bounce rate + spam complaint monitoring
→
📊

Deliverability Monitoring

Bounce rates and spam complaint rates watched throughout the warming period. If either spikes, we slow the ramp and investigate before continuing. Domain reputation is easier to protect than it is to repair.

Monitoring (not a sequence)
Then Sequence 14 fires. Once the domain has reputation, the phased activation batch sends go out and land in inboxes. Not before.

After the Reviewer Acts

Reviewers log into their portal and mark an application approved, declined, or incomplete. Each decision fires a different sequence.
Reviewer decision
Approved: WPIT path (references required)
→
4

Reference Request (Form C), x3

Sends the Form C link to each of the 3 required references individually. Multi-fire: one email per reference, tracked separately. At least one must be a PWS.

To: each reference
WordPress trigger
Each individual Form C submitted
→
5

Reference Received Notification

Notifies the applicant each time one reference submits. Fires once per reference, not once per applicant. So if 2 of 3 are in, the applicant knows exactly where they stand.

To: applicant
WordPress trigger
Third (final) Form C submitted
→
6

All References Complete Notification

All 3 in. Tells the applicant the final review window (24-72 hours) so they stop watching their inbox every hour and stop emailing staff.

To: applicant

Active Certificate Holders

Renewal Reminder Series (90 / 60 / 30 Days)

Three touchpoints before the renewal deadline. Stop trigger: the moment a renewal application is submitted, all pending reminders in the series cancel immediately. People who already renewed never get nagged.
